# Сборка Vantara

Два режима: быстрый прототип интерфейса и полная сборка форка.

---

## Режим 1 — Прототип интерфейса

Ничего компилировать не нужно. Цикл правки — секунды.

### Требования

- Firefox Developer Edition (или Nightly / обычный Firefox)
- PowerShell

### Запуск

```powershell
.\tools\dev-profile.ps1
```

Скрипт создаст профиль в `.dev-profile`, подключит к нему `ui/chrome` через
junction и запустит браузер.

Если Firefox не установлен, скрипт скачает portable-сборку в `.dev-runtime`,
не трогая систему:

```powershell
.\tools\dev-profile.ps1 -Fetch
```

### Работа

| Действие | Как |
|---|---|
| Применить правки CSS | `Ctrl+Alt+R` в окне браузера |
| Отладчик интерфейса | `Ctrl+Alt+Shift+I` (Browser Toolbox) |
| Чистый профиль | `.\tools\dev-profile.ps1 -Reset` |

В Browser Toolbox доступен инспектор по интерфейсу браузера так же, как по
обычной странице: можно найти нужный селектор и проверить правило на месте.

### Проверка интерфейса

Скриншот показывает результат, но не объясняет причину: правило не сработало
из-за опечатки, из-за незагруженного файла или потому что Firefox перекрыл
его своим. Два инструмента отвечают на это точно, читая живое окно браузера
через Marionette — штатный протокол автоматизации Mozilla.

Браузер для этого запускается в режиме инспекции:

```powershell
.\tools\dev-profile.ps1 -Inspect
```

| Команда | Что отвечает |
|---|---|
| `python tools/inspect-ui.py` | Дошли ли токены, какие правила выиграли у Firefox |
| `python tools/audit-selectors.py` | Есть ли селекторы, которые ни к чему не относятся |
| `.\tools\screenshot.ps1` | Снимок окна в `docs/screenshots/` |

**Запускать после каждого обновления движка.** Firefox меняет разметку chrome
между версиями, и устаревший селектор не даёт никакой ошибки — правило просто
молча перестаёт работать. Так в Firefox 157 фон адресной строки переехал
с `#urlbar-background` на `.urlbar-background`, и половина интерфейса осталась
стандартной при полностью «рабочем» на вид CSS.

### Тесты

```bash
node tools/test-url-parse.mjs
```

Проверяет разбор ввода адресной строки: что уходит в поисковую систему,
а что открывается напрямую. Ошибка здесь означает утечку — внутренний хост
вроде `router.local` или `intranet.company.ru` ушёл бы в поисковик вместе
с путём. Набор случаев только растёт, удалять из него нельзя.

## Режим 2 — Сборка форка

> Этап 3 роадмапа. Раздел описывает целевой процесс; окружение ещё не разворачивалось.

### Требования

| Что | Зачем | Объём |
|---|---|---|
| MozillaBuild | Оболочка сборки Mozilla под Windows | ~500 МБ |
| Visual Studio 2022 + C++ workload, Windows SDK | Компилятор | ~10 ГБ |
| Rust (stable, MSVC target) | Часть Gecko на Rust | ~2 ГБ |
| Node.js 18+ | surfer и сборочные скрипты | — |
| Git, Python 3.9+ | Инструменты Mozilla | — |
| **Свободное место** | Исходники + объектные файлы | **~60 ГБ** |

На этой машине уже есть: Node 22, Python 3.12, Rust 1.98, Git, VS 2022.
Не хватает **MozillaBuild** — https://ftp.mozilla.org/pub/mozilla/libraries/win32/MozillaBuild-Latest.exe

### Порядок

```bash
# 1. Инструмент сборки форков (написан командой Zen Browser)
npm install -g @zen-browser/surfer

# 2. Инициализация проекта: версия Firefox, имя приложения, бренд
surfer init

# 3. Скачать исходники Firefox в engine/ (~30 ГБ, долго)
surfer download

# 4. Наложить наш оверлей src/ и патчи на исходники
surfer import

# 5. Сборка. Первый раз — 1-3 часа, дальше инкрементально
surfer build

# 6. Установщик
surfer package
```

### Обновление до новой версии Firefox

```bash
surfer update <версия>   # поднять версию движка
surfer import            # заново наложить наши изменения
```

Конфликты патчей вылезут на шаге `import` — их видно сразу, а не после сборки.
Для браузера с упором на защиту данных отставание от Firefox по патчам
безопасности недопустимо, поэтому обновление — регулярная операция, а не разовая.

### Что попадает в сборку

| Из репозитория | Куда в Firefox |
|---|---|
| `ui/chrome/vantara/*.css` | `src/browser/themes/vantara/` |
| `ui/prefs/user.js` | `src/browser/app/profile/vantara.js` (заводские дефолты) |
| `ui/pages/newtab/` | `src/browser/components/newtab/vantara/` |
| `brand/icons/` | `src/browser/branding/vantara/` |
| chrome-скрипты этапа 2 | `src/browser/base/content/vantara/` |

### Типичные грабли

- **Сборка падает на нехватке места** — объектные файлы занимают больше самих
  исходников. Держать 60 ГБ свободными.
- **Антивирус тормозит сборку в разы** — исключить `engine/` и `obj-*` из
  проверки в реальном времени.
- **Долгий путь к файлам** — Windows и глубокая вложенность Gecko конфликтуют.
  Собирать близко к корню диска.
- **Изменения в `src/` не видны** — забыт `surfer import` перед `build`.
